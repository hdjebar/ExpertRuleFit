# Findings from the Phase A session (22/11/2026)

Environment: fresh `pip install -e ".[dev]"` on Python 3.13 → scikit-learn 1.9.1, scipy 1.18.1, numpy 2.5.5, imodels 3.0.4, interpret 0.7.8. This is **not** the pinned stack the README benchmark ran on, so treat the numbers below as observations in this environment until reproduced in the container.

## 1. Default `confirmatory_penalty=1e-8` can collapse the model (open — needs a decision)

Adding a single confirmatory rule can wipe out every generated rule.

| Setting (standardised synthetic credit data, n = 500, `max_rules=20`, `n_bootstrap=3`) | Stable features | Active | Train AUC |
|---|---|---|---|
| no confirmatory rule | 21 | 18 | 0.951 |
| 1 confirmatory rule, w_c = 1e-8 (default) | 15 | 15 | **0.673** |
| 1 confirmatory rule, w_c = 1e-4 | 26 | 26 | 0.956 |
| 1 confirmatory rule, w_c = 1e-2 | 23 | 23 | 0.957 |

In a second synthetic case (the absorption fixture in `tests/test_confirmatory_diagnostics.py`, w_c = 1e-4), 13 features passed the bootstrap filter, but the final model kept only the two confirmatory rules non-zero. One of them, a pure 0/1 alternating "noise" rule, got a coefficient of about −0.98.

**Likely mechanism (not yet confirmed):** rescaling by 1/√w_c multiplies confirmatory columns by 10⁴. saga's step size is set by the largest row norm, so the other coefficients barely move from zero and the convergence test is met early. One final fit stopped after 34 iterations. The CV choice of C (scored by accuracy) may also play a part.

**Unscaled inputs hit the same problem.** On the unstandardised test fixture (a lognormal column ≈ 10³–10⁵), ExpertRuleFit gives train AUC ≈ 0.54 even with no confirmatory rule. The benchmark standardises inputs, so the README numbers are unaffected, but the library doesn't standardise or warn.

**Options:** (a) lower the default to w_c ≈ 1e-4 and check with B3; (b) standardise columns internally before weighting; (c) give confirmatory rules a separate unpenalised block (e.g. two-stage, or L-BFGS-B with an L1 proximal step, which overlaps C3); (d) at minimum, warn when inputs are unscaled. Whichever is chosen, rerun the 100-seed benchmark: (b) changes the default model.

**Claims impact:** "Confirmatory rules are always included" is still true, but in these cases including them degraded the rest of the model. Phase B3 (sensitivity grid over w_c) is now the priority check.

## 2. Five tests failed on `main` in a fresh environment (fixed on this branch)

- `DualModel.explain`: scipy now returns COO from `csr.multiply()`, so row indexing broke. Fixed by converting to CSR in `_build_predict_matrix`.
- 4 tests in `test_validation.py` expected error messages the code didn't produce, and a 1-D `X` raised `IndexError` before validation ran. Fixed.

## 3. Benchmark script vs paper

- `load_taiwan_credit` subsamples **5,000 of 30,000 rows** (seed 42). The paper says "Taiwan Credit (UCI, 30,000 rows)". Either state the subsample or rerun on all rows.
- `preprocess` fits the imputer and scaler on the full dataset before the train/test split (mild leakage). B1 fits preprocessing inside each training set.
- The benchmark uses `tol=1e-6` for ExpertRuleFit; the library default is `1e-4`.

## 4. Runtime (input for C4)

One ExpertRuleFit fit with the benchmark settings (250 trees, 50 rules, 10 bootstraps, 3-fold CV over 6 l1 ratios × 10 Cs, saga, tol 1e-6) on 720 German Credit rows took **1,803 s** single-threaded here. RuleFit took about 3 s. Full B1 needs 240 ERF fits per dataset, so plan a multi-core machine (`--jobs N`) or reduce the grid/tolerance and say so in the paper.

## 5. Other observations

- With scikit-learn 1.9, imodels' internal logistic call emits "Inconsistent values: penalty=l1 with l1_ratio=0.0", so RuleFit's L1 may be running as L2 in this stack. Pin scikit-learn (< 1.8 or the container version) for anything reported.
- `DualGlassBox` fits its EBM with `n_jobs=-1`, which sits outside the determinism envelope.
- The README still uses "stability" without "across seeds" in several places (headline table, "Two Guarantees", comparison section). Narrow it in Phase D, per `CLAIMS_POLICY.md`.
