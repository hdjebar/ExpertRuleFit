# Findings from the Phase A session (22/11/2026)

Environment for §1–§5: fresh `pip install -e ".[dev]"` on Python 3.13 → scikit-learn 1.9.1, scipy 1.18.1, numpy 2.5.5, imodels 3.0.4, interpret 0.7.8. This is **not** a pinned stack; treat these numbers as diagnostics. The pinned stack created afterwards is in `docker/` (§6).

## 1. Default `confirmatory_penalty=1e-8` can collapse the model (cause confirmed; fixed in 0.7.0)

Adding a single confirmatory rule can wipe out every generated rule.

| Setting (standardised synthetic credit data, n = 500, `max_rules=20`, `n_bootstrap=3`) | Stable features | Active | Train AUC |
|---|---|---|---|
| no confirmatory rule | 21 | 18 | 0.951 |
| 1 confirmatory rule, w_c = 1e-8 (old default) | 15 | 15 | **0.673** |
| 1 confirmatory rule, w_c = 1e-4 | 26 | 26 | 0.956 |
| 1 confirmatory rule, w_c = 1e-2 | 23 | 23 | 0.957 |

In a second synthetic case (the absorption fixture in `tests/test_confirmatory_diagnostics.py`, w_c = 1e-4), 13 features passed the bootstrap filter, but the final model kept only the two confirmatory rules non-zero. One of them, a pure 0/1 alternating "noise" rule, got a coefficient of about −0.98.

**Unscaled inputs hit the same problem.** On the unstandardised test fixture (a lognormal column ≈ 10³–10⁵), ExpertRuleFit gave train AUC ≈ 0.54 even with no confirmatory rule.

### 1a. Cause: saga stops early, without a warning, when one column is 10⁴ times larger

Scripts and raw results: `experiments/diagnostics/` (`diag_saga.py`, `diag_cv.py`, `diag_saga_std.py` and their `.json`). The design matrix is the collapsing case above: 6 linear terms + 19 RuleFit rules + 1 confirmatory rule (`country_risk > 2.5`). Environment: scikit-learn 1.9.1 (not the pinned stack; these are solver diagnostics, not results for the paper).

**Fixed C (= 1, l1_ratio = 0.5), so CV plays no part.** Each fit is run twice: library settings (tol 1e-4, max_iter 10,000) and a reference run (tol 1e-12, up to 2,000,000 iterations). The objective is C·NLL + elastic-net penalty in the solver's parametrisation.

| Column rescaling | max ‖row‖² (step ∝ 1/this) | saga iterations | ConvergenceWarning | Objective above reference | Confirmatory coef: saga / reference |
|---|---|---|---|---|---|
| w_c = 1e-8 | 1.0 × 10⁸ | 9,465 | **none** | **156.0** | **−1.06 / +0.23** |
| w_c = 1e-4 | 1.0 × 10⁴ | 2,548 | none | 0.71 | −0.02 / −0.10 |
| none (w = 1) | 71 | 282 | none | 0.0002 | 0 / 0 |

With w_c = 1e-8 the reference run itself did not converge in 2,000,000 iterations (one ConvergenceWarning). The library-setting fit stopped silently at an objective 156 units worse, with the confirmatory coefficient of the wrong sign.

**CV, as in the pipeline's final step** (`LogisticRegressionCV`, saga, 5 folds × 10 Cs × 6 l1 ratios):

| Column rescaling | Chosen C | saga iterations per fit: min / median / max | ConvergenceWarnings | Confirmatory coef |
|---|---|---|---|---|
| w_c = 1e-8 | 0.046 | **2 / 17** / 9,827 | **0** | −1.06 |
| w_c = 1e-4 | 2.78 | 1 / 169 / 2,974 | 0 | +0.13 |
| none | 0.36 | 1 / 108 / 1,826 | 0 | 0 |

**Conclusion.** The hypothesis holds. saga's step size is about 1/max‖row‖². With one column multiplied by 1/√w_c = 10⁴, the step is about 10⁶ times smaller than without rescaling, so the other coefficients barely move. saga's stopping rule (relative coefficient change < tol) is then met after a handful of iterations. scikit-learn raises no ConvergenceWarning because the criterion *was* met. The solution is far from the optimum (here with the wrong sign on the confirmatory coefficient), and since the CV and the bootstrap filter both rely on these fits, generated rules drop out.

### 1b. Fix in 0.7.0: internal standardisation + default w_c = 1e-4

- `standardize=True` (new, default): candidate columns are standardised with training statistics (linear terms centred and scaled; rule and expert columns scaled only, to stay sparse), stored for prediction and covered by `save`/`load`. Coefficients and the intercept are reported on the original scale. Models saved before 0.7 load as unstandardised.
- `confirmatory_penalty` default 1e-8 → 1e-4.

End-to-end check on the **unscaled** fixture (n = 500, `max_rules=20`, `n_bootstrap=3`; scikit-learn 1.9.1):

| standardize | Confirmatory rule | w_c | Stable | Active | Train AUC |
|---|---|---|---|---|---|
| False | none | – | 2 | 2 | 0.535 |
| False | yes | 1e-8 | 3 | 3 | 0.500 |
| False | yes | 1e-4 | 3 | 3 | 0.509 |
| True | none | – | 16 | 16 | 0.953 |
| True | yes | 1e-8 | 23 | 23 | **0.681** |
| True | yes | 1e-4 | 24 | 20 | 0.947 |
| True | yes | 1e-2 | 24 | 19 | 0.947 |

Standardisation fixes unscaled inputs; the collapse with a confirmatory rule needs the smaller weight ratio as well (standardise + 1e-8 still collapses).

**Caveat: 1e-4 is not fully accurate either.** The fixed-C test on standardised columns (`diag_saga_std.json`):

| w_c | max ‖row‖² | Objective above reference | Largest coefficient error | Confirmatory coef: saga / reference |
|---|---|---|---|---|
| 1e-8 | 4.0 × 10⁸ | 160.4 | 1.22 | −1.02 / +0.20 |
| 1e-4 | 4.0 × 10⁴ | **1.39** | **1.05** | −0.10 / −0.17 |
| 1e-2 | 520 | 0.017 | 0.24 | −0.15 / −0.16 |
| 1e-1 | 160 | 0.002 | 0.08 | −0.13 / −0.14 |
| 1 | 124 | 0.001 | 0.06 | −0.03 / −0.04 |

At w_c = 1e-4 one coefficient is still off by about 1 at the library tolerance. B3 (the w_c grid on the three credit datasets, pinned stack) decides whether the default should move to about 1e-2. Option 3 (a separate unpenalised, sign-constrained confirmatory block, which removes the rescaling altogether) is deferred to Phase C with C3.

**Claims impact:** "Confirmatory rules are always included" is still true. Up to 0.6.0, including them could silently degrade the rest of the model.

## 2. Five tests failed on `main` in a fresh environment (fixed on this branch)

- `DualModel.explain`: scipy now returns COO from `csr.multiply()`, so row indexing broke. Fixed by converting to CSR in `_build_predict_matrix`.
- 4 tests in `test_validation.py` expected error messages the code didn't produce, and a 1-D `X` raised `IndexError` before validation ran. Fixed.

## 3. Benchmark script vs paper

- `load_taiwan_credit` subsamples **5,000 of 30,000 rows** (seed 42). The paper said "Taiwan Credit (UCI, 30,000 rows)". **Fixed:** the paper now states the subsample.
- `preprocess` fitted the imputer, encoder and scaler on the full dataset before the train/test split (mild leakage). **Fixed:** `expertrulefit_validation.py` now fits them on the training split only; the paper says Table 1 predates this and will be regenerated on the pinned stack. B1 also preprocesses inside each training set.
- The benchmark uses `tol=1e-6` for ExpertRuleFit; the library default is `1e-4`.

## 4. Runtime (input for C4)

One ExpertRuleFit fit with the benchmark settings (250 trees, 50 rules, 10 bootstraps, 3-fold CV over 6 l1 ratios × 10 Cs, saga, tol 1e-6) on 720 German Credit rows took **1,803 s** single-threaded here. RuleFit took about 3 s. Full B1 needs 240 ERF fits per dataset, so plan a multi-core machine (`--jobs N`) or reduce the grid/tolerance and say so in the paper.

## 5. Other observations

- With scikit-learn 1.9, imodels' internal logistic call emits "Inconsistent values: penalty=l1 with l1_ratio=0.0", so RuleFit's L1 may be running as L2 in this stack. Pin scikit-learn (< 1.8 or the container version) for anything reported.
- `DualGlassBox` fits its EBM with `n_jobs=-1`, which sits outside the determinism envelope.
- The README still uses "stability" without "across seeds" in several places (headline table, "Two Guarantees", comparison section). Narrow it in Phase D, per `CLAIMS_POLICY.md`.

## 7. B3 sensitivity: German Credit, pinned stack (23/11/2026)

Run: `experiments/sensitivity.py` in the `docker/` image (scikit-learn 1.7.2), ExpertRuleFit 0.7.0 defaults (standardise, tol 1e-4), single stratified 80/20 split (seed 42). Rules: confirmatory "checking account < 0 DM" (`Attribute1 == A11`, expected +1), optional "duration > 24 months" (expected +1). Results: `experiments/results/sensitivity/` (`fits.jsonl`, `summary.csv`, `table.md`, `sensitivity.png`). HMEQ and Taiwan not run (13–17 min per German fit; their training sets are 5–6× larger).

Averages over the three w_o values (each cell: min–max across w_o):

| w_c | Test AUC | Brier | ConvergenceWarnings per fit | Fit time (s) | Confirmatory coef | Sign vs expected +1 |
|---|---|---|---|---|---|---|
| 1e-8 | 0.753–0.756 | 0.228–0.229 | 360–361 | ~1,040 | +0.06 to +0.07 | OK |
| 1e-6 | 0.795–0.797 | 0.154–0.155 | 66–69 | ~945 | +0.25 to +0.27 | OK |
| 1e-4 (default) | 0.785–0.787 | 0.169–0.171 | 3–6 | 790–865 | −1.41 to −1.65 | **contradicted** |
| 1e-2 | 0.793–0.797 | 0.158–0.163 | **0** | 260–275 | −0.62 to −1.25 | **contradicted** |
| 1 | 0.784–0.793 | 0.158–0.171 | **0** | 130–140 | −0.30 to −1.55 | **contradicted** |

Observations:

1. **Solver health.** In the pinned stack (unlike scikit-learn 1.9 in §1a), saga does raise ConvergenceWarnings, and their number falls monotonically with w_c: hundreds per fit at 1e-8, a few at the 1e-4 default, none from 1e-2. Fit time falls by 3× from 1e-4 to 1e-2.
2. **Accuracy.** w_c = 1e-8 still degrades the model even with standardisation (AUC −0.03 to −0.04, Brier 0.229 vs about 0.16). From 1e-6 upwards, AUC varies within 0.784–0.797 on one split, which is within the run-to-run spread to expect from a single 200-row test set. No w_c ≥ 1e-6 is clearly better on discrimination.
3. **Sign flip is real, not a solver artefact.** In the fits without convergence warnings (w_c ≥ 1e-2), the coefficient of "checking account < 0 DM" is negative, while the rule is marginally risk-increasing (49 % bad vs 30 % overall). The model also keeps `linear:Attribute1` (the ordinal checking-status code, max |corr| 0.77 with the rule) and several generated rules with the clause `Attribute1 <= 0.5`, which is the same condition. Those terms carry the effect, and the conditional coefficient of the expert rule turns negative. The A2 sign check flags it (`confirmatory_sign_ok_ = False`) and the diagnostics name `linear:Attribute1` as the most correlated term. The positive signs at 1e-8 and 1e-6 come from fits with 66–361 ConvergenceWarnings and should not be read as "the expert's sign holds".
4. **Rule-set sensitivity.** Jaccard against the default rule set is 0.92–1.00 for w_c ∈ {1e-6, 1e-4} and 0.75–0.79 for w_c ∈ {1e-2, 1}; w_o matters less than w_c.
5. **Optional rule** ("duration > 24 months") was kept in every fit.

**Recommendation (pending HMEQ/Taiwan):** w_c in [1e-2, 1]. In this run, that is the range with no ConvergenceWarnings, AUC within the default's range or better, and fits 3–6× faster. Below 1e-2 the solver is not reliable, and the confirmatory coefficient there is not interpretable. The default was not changed in this session: it stays at 1e-4 as decided, pending your call. The German result also strengthens the case for C3: what an expert needs from a confirmatory rule is a sign-constrained, unpenalised block, not a near-zero weight.
